<h3 id="merchant-history">User transaction history</h3>

`userDepositCount`:

1. Counting rules: Count only this user’s payout orders on the merchant platform that have reached a final successful status. Exclude orders that are pending payment, canceled, failed, refunded, or reversed.
2. Boundary rules: `0` or omission means the user has no historical successful payouts on the merchant platform, or has not yet completed their first payout.
3. Usage: This is one reference factor for payout risk assessment and routing. The platform combines it with its own transaction history to make an overall decision.

`userFirstDepositTime`:

1. Counting rules: Use the completion or crediting time of the user’s first successful payout order on the merchant platform, rather than the user’s registration time or the current request time.
2. Boundary rules: Omit this field when `userDepositCount` is `0` or there are no historical successful payouts. Supply a valid 13-digit millisecond timestamp no later than the current request time. The platform will disregard this reference value if it is invalid or inconsistent with the payout count.
3. Usage: This is one reference factor for payout risk assessment and routing. The platform combines it with its own transaction history to make an overall decision.
