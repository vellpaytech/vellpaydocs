# 订单状态

VellPay 使用字符串状态表示订单当前阶段。创建接口返回处理中状态并不代表交易最终成功；商户应结合查询接口和异步回调确认最终结果。

## 代收与收银台状态

| 状态 | 说明 | 是否终态 |
|---|---|---|
| `INIT` | 订单已受理，等待进入支付流程 | 否 |
| `PAYING` | 支付处理中 | 否 |
| `SUCCESS` | 代收成功 | 是 |
| `FAIL` | 代收失败 | 是 |
| `REFUND` | 代收款项已退款 | 是 |

## 代付状态

| 状态 | 说明 | 是否终态 |
|---|---|---|
| `INIT` | 代付已受理 | 否 |
| `PAYING` | 代付处理中 | 否 |
| `SUCCESS` | 代付成功 | 是 |
| `FAIL` | 代付失败 | 是 |
| `REFUND` | 代付款项已全部退回 | 是 |
| `PART_REFUND` | 代付款项已部分退回 | 是 |

## 接入建议

- 不要仅根据 HTTP 状态码或响应 `code` 判断交易结果。
- `INIT`、`PAYING` 为非终态，应继续接收回调或主动查询。
- 对同一订单的重复回调应按 `tradeNo` 和状态做幂等处理。
- 若查询结果与回调不一致，以平台最终状态为准，并联系技术支持核查异常的状态反转。

## KYC 状态

| 状态 | 说明 | 是否终态 |
|---|---|---|
| `PENDING` | 等待用户认证 | 否 |
| `REVIEWING` | 认证审核中 | 否 |
| `APPROVED` | 认证通过 | 是 |
| `REJECTED` | 认证被拒绝 | 是 |
| `FILA` | 认证失败（接口保留状态名） | 是 |
